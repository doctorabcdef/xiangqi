# 弈间 · 中国象棋

中国象棋网页游戏：人机对弈、本地双人、自动保存和跨设备续局。前端部署于 GitHub Pages，云端使用 Cloudflare Worker + D1，由 Sites 托管。

## 使用

- 点击棋子，再点击绿色落点。人机模式中你执红棋，可选入门、进阶、挑战三档难度。
- 每次走子自动保存在本机并同步云端。再次打开同一浏览器会恢复上次棋局与对弈设置。
- **跨设备：**在另一台设备打开同一个网址，即自动恢复同一盘云端棋局。无需注册、登录或输入同步码。按用户要求，默认棋局是公开共享的，所有访问这个网址的人都能查看、落子、悔棋和开始新局。
- 查看右上角“已同步到云端”后再换设备。离线时会保留本机进度，联网后重试。两台设备存在不同进度时，必须选择保留哪一份，可先导出备份。
- 支持悔棋、翻转、导出和导入 JSON 棋谱。人机悔棋会撤销完整一轮（电脑尚未落子时只撤销玩家一步）。
- 本地缓存属于当前浏览器；清理浏览器数据后仍会自动恢复默认共享棋局的云端进度。高级设置支持按棋局标识连接其他已有棋局。导出的棋谱不包含同步码。

## 规则与范围

实现车、马、炮、象、士、将帅、兵卒的走子限制，马腿、象眼、过河兵、将帅照面、自陷将军、将死和困毙判负。休闲模式下同一行棋方的相同局面出现三次判和；不实现专业比赛的长将、长捉裁定。单盘最多保存 1000 手。电脑基于限时迭代加深搜索，并非专业棋力引擎。双人模式为同屏对弈；跨设备同步用于续局，不提供在线匹配。

## 本地开发与验证

需要 Node.js 24：

```sh
npm ci
npm --prefix cloud run build
npm test
npm run dev
```

访问 `http://127.0.0.1:4173`。`npm run build` 生成纯静态 `dist/`，资源均使用相对路径，兼容 GitHub 项目路径。

浏览器测试：`npm run test:browser`。默认使用 Windows 上已安装的 Edge；其他环境可设置 `EDGE_PATH` 指向 Chromium 浏览器。测试使用隔离的模拟云端，不读写真实用户棋局。

## 部署

前端目标：`https://doctorabcdef.github.io/xiangqi/`。仓库提供 `.github/workflows/pages.yml`：推送 main 时验证并发布。在 GitHub 仓库 Settings → Pages 中，发布源选择 **GitHub Actions**。也可发布构建产物到 gh-pages 分支并采用该分支的根目录。

`cloud/` 是云同步服务的完整源码。`src/config.js` 指向该服务的 HTTPS 地址。服务部署时需 D1 的 `DB` 绑定，并执行 `cloud/drizzle/` 下的迁移；`npm --prefix cloud run build` 生成 `cloud/dist/server/index.js`。迁移文件已提交，重新生成仅在修改 schema 时执行：`npm --prefix cloud ci`、`npm --prefix cloud run db:generate`。

云服务仅允许本站来源和本地开发来源进行浏览器跨域访问。默认共享棋局采用公开固定标识，前端通过该标识访问同一盘棋；这不是私密房间。数据库以棋局标识的 SHA-256 摘要索引，不保存标识原文。其他棋局按不同标识隔离。API 使用版本号条件更新，避免并发设备静默覆盖。服务会校验棋谱合法性和大小，不在网页内嵌服务密钥。

## 文件

- `src/engine.js`：规则、棋谱与终局判定。
- `src/ai.js`、`src/ai-worker.js`：后台线程中的电脑搜索。
- `src/app.js`：棋盘界面与交互。
- `src/sync.js`：本机缓存、云端同步、离线重试及版本冲突。
- `cloud/worker.js`：云端 API 与数据库访问。
- `tests/`：规则、同步、API 及浏览器验证。
