# 弈间 · 中国象棋

中国象棋网页游戏：人机对弈、本地双人、自动保存和跨设备续局。前端部署于 GitHub Pages，云端使用 Cloudflare Worker + D1，由 Sites 托管。

## 使用

- 点击棋子，再点击绿色落点。人机模式可选择执红或执黑，以及入门、进阶、挑战三档难度；红方始终先行，选择执黑后电脑会执红先走。换边会确认并开始新局，我方默认显示在棋盘下方。执棋方设置随棋局自动保存和同步，旧棋谱默认玩家执红。
- 每次走子自动保存在本机并同步云端。再次打开同一浏览器会恢复上次棋局与对弈设置。
- **跨设备：**在另一台设备打开同一个网址，即自动恢复同一盘云端棋局。无需注册、登录或输入同步码。按用户要求，默认棋局是公开共享的，所有访问这个网址的人都能查看、落子、悔棋和开始新局。
- 查看右上角“已同步到云端”后再换设备。离线时会保留本机进度，联网后重试。两台设备存在不同进度时，必须选择保留哪一份，可先导出备份。
- 页面在前台时优先使用 WebSocket 长连接上传落子、接收棋局变更；同步详情中显示“实时连接”。连接失败时自动恢复 250 毫秒间隔的 HTTP 检查，慢请求不会重叠；切到后台暂停连接，回到前台立即恢复。保存失败保留本机进度并退避重试，丢失保存响应时核对版本，避免重复落子。实际延迟仍受网络与数据库响应时间影响。
- 支持悔棋、翻转、导出和导入 JSON 棋谱。人机悔棋会撤销完整一轮（电脑尚未回应时只撤销玩家一步），回到玩家最近一次落子之前。玩家执黑时保留电脑的红方开局着法；玩家还未落子时不能悔棋。
- 棋盘左侧分别展示“黑方吃掉”和“红方吃掉”的棋子，保留棋盘上的圆形外观和原本的红黑颜色；手机上展示框排列在棋盘下方。悔棋、刷新、导入和跨设备恢复时，吃子展示会随棋局一起更新。右侧操作区和棋盘下方均可悔棋。
- 本地缓存属于当前浏览器；清理浏览器数据后仍会自动恢复默认共享棋局的云端进度。高级设置支持按棋局标识连接其他已有棋局。导出的棋谱不包含同步码。
- “棋间聊两句”位于“当前对局／对局棋谱”一列的右侧，窄屏自动上下排列，支持昵称、文字、表情、快捷文字和语音。默认聊天记录所有访客可见，自动保存在云端；刷新或换设备可以继续查看，“更早消息”可加载历史。重开棋局、悔棋不会删除聊天。高级设置连接其他棋局时，聊天也随棋局切换。
- 两个语音按钮发送并播放用户提供的原始音频：“太慢了太慢了”对应 `梦辰艺术.m4a`，“搞快点好不”对应 `梦辰艺术 2.m4a`。同一棋局中所有打开的页面默认尝试自动播放新语音，无需声音开关，旧版本的本机静音设置不再生效。允许自动播放的浏览器打开页面即可接收声音；浏览器若拦截首次自动播放，点击棋盘或页面、按键会自动解锁，并显示必要的文字提示。网页不能强制绕过浏览器的声音权限。刷新、首次载入和查看更早记录不会自动播放历史语音，点击聊天气泡可以手动重播。新语音按消息 ID 去重并顺序播放，不依赖昵称区分设备。昵称最多 20 字，文字最多 500 字，表情按 UTF-16 长度计数。未发出的消息保存在本机，刷新后仍会重试，并通过消息标识避免重复保存。
- 切换后台后仍尝试接收语音，但浏览器冻结标签页、手机锁屏或系统暂停音频时，不能保证即时播放。等待浏览器允许播放的队列最多保留 20 条、30 秒，较早语音可在聊天记录中手动重播。

## 规则与范围

实现车、马、炮、象、士、将帅、兵卒的走子限制，马腿、象眼、过河兵、将帅照面、自陷将军、将死和困毙判负。休闲模式下同一行棋方的相同局面出现三次判和；不实现专业比赛的长将、长捉裁定。单盘最多保存 1000 手。电脑基于限时迭代加深搜索，并非专业棋力引擎。双人模式为同屏对弈；跨设备同步用于续局，不提供在线匹配。

## 本地开发与验证

需要 Node.js 24：

```sh
npm ci
npm --prefix cloud run build
npm test
npm run dev
```

访问 `http://127.0.0.1:4173`。`npm run build` 生成纯静态 `dist/`，资源均使用相对路径，兼容 GitHub 项目路径。

浏览器测试：`npm run test:browser`。默认使用 Windows 上已安装的 Edge；其他环境可设置 `EDGE_PATH` 指向 Chromium 浏览器。测试使用隔离的模拟云端，不读写真实用户棋局。

## 部署

前端地址：`https://doctorabcdef.github.io/xiangqi/`。源码位于 `main` 分支，构建产物位于 `gh-pages` 分支，GitHub Pages 使用 `gh-pages` 的根目录发布。`.github/workflows/checks.yml` 会在 main 更新时执行测试和构建，并保存网页产物。更新网页时，应将新的 `dist/` 内容发布到 gh-pages；源码检查不会绕过仓库的部署分支保护规则。

`cloud/` 是云同步服务的完整源码。`src/config.js` 指向该服务的 HTTPS 地址。服务部署时需 D1 的 `DB` 绑定，并执行 `cloud/drizzle/` 下的迁移；`npm --prefix cloud run build` 生成 `cloud/dist/server/index.js`。迁移文件已提交，重新生成仅在修改 schema 时执行：`npm --prefix cloud ci`、`npm --prefix cloud run db:generate`。

云服务仅允许本站来源和本地开发来源进行浏览器跨域访问。默认共享棋局采用公开固定标识，前端通过该标识访问同一盘棋；这不是私密房间。数据库以棋局标识的 SHA-256 摘要索引，不保存标识原文。其他棋局按不同标识隔离。API 使用版本号条件更新，避免并发设备静默覆盖。服务会校验棋谱合法性和大小，不在网页内嵌服务密钥。

实时接口为 `/api/live`，通过 WebSocket 子协议传递棋局标识，不将其放入网址。每条连接以 100 毫秒加查询耗时的间隔检查 D1 主库，仅推送新版本；每次查询使用新的 `first-primary` 会话，不依赖不同 Worker 实例共享内存。连接在 36 次查询后自动续期，低于 50 次查询预算；超时、断线时同一份写入可通过 HTTP 的 CAS 校验恢复。此实现是持久连接加服务端数据库检查，不是 D1 原生事件订阅。

聊天接口为 `/api/chat`，使用相同的棋局标识认证，在独立的 `chat_messages` 表保存记录。GET 返回最新 50 条，`before` / `after` 序号支持历史与增量查询；POST 按房间和消息 UUID 幂等写入。每 500 毫秒尝试检查新聊天，不重叠读取，后台间隔受浏览器调度限制；发送立即提交，聊天请求独立于棋局同步。音频位于 GitHub Pages 的 `assets/voices/`，数据库只记录预设语音标识。

## 文件

- `src/engine.js`：规则、棋谱与终局判定。
- `src/ai.js`、`src/ai-worker.js`：后台线程中的电脑搜索。
- `src/app.js`：棋盘界面与交互。
- `src/sync.js`：本机缓存、云端同步、离线重试及版本冲突。
- `src/live.js`：实时连接、心跳、自动重连与请求确认。
- `src/chat.js`、`cloud/chat.js`：聊天界面、离线发送、历史查询和云端持久化。
- `src/chat-audio.js`：声音解锁、新语音顺序播放、去重与房间切换清理。
- `cloud/worker.js`：云端 API 与数据库访问。
- `cloud/store.js`、`cloud/live.js`：HTTP/实时连接共用的版本控制、存储及变更推送。
- `tests/`：规则、同步、API 及浏览器验证。
